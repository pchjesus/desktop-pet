## 1. 조사된 Electron 현황 (main의 코드만 읽음; 실행 검증 아님)

- `src/pet-engine.js`: `IDLE/WALK/SIT/SLEEP/DRAG/REACT` 6개 공통 상태; 이동 위치 계산과 상태 결정 담당.
- `src/renderer.js`: 각 캐릭터에 `setState(), setFacing(), render()` 연결; 사용자 클릭과 드래그 구별; 이동 중 Main에 창 위치 전송. 일부 캐릭터에서 선택적 `setMovementDirection(), getMovementSpeed(), startSpecialAction()` 사용.
- `src/main.js`: 기존 펫 창 크기 180×150 DIP, 중심 클릭 판정 110×110 영역, 창 이동 및 모니터 작업 영역 보정.
- `src/window-bounds.js`: 캐릭터별 외형 bounding envelope가 기존 5종에만 정의됨. SD 인체의 머리/팔/스커트 크기는 별도 실측 필요.
- `src/start.html`: 기존 5종 중 하나를 선택해 시작하는 UX. 3인 동시 실행은 현재 합의/구현되지 않음.
- 현재 Main의 기존 5종/IPC/동작 확률/시간값을 신규 SD의 필요만으로 변경하지 않는다.

## 2. 제안하는 실제 화면 동작 (아직 사용자 미승인)

| 캐릭터 | IDLE (작게 계속) | 클릭 REACT (한 번) | 움직임에서 주의할 점 |
|---|---|---|---|
| 지우 | 자연스러운 눈 깜빡임, 미세한 호흡, 단발 머리끝의 작은 움직임 | 이미 들어 올린 손을 손목 중심으로 1~2번 흔든 뒤 복귀 | 파란 상의·흰 스커트와 손의 방향 고정, 웃는 얼굴 유지 |
| 설윤 | 눈 깜빡임, 고개 아주 작은 기울임, 긴 머리카락의 느린 움직임 | 모은 손 자세를 유지한 짧은 인사/고개 끄덕임 | 손 분리하지 않기, 긴 머리/프릴 변형 방지 |
| 세은 | 눈 깜빡임, 볼 옆 손가락 포즈 유지, 단발 끝부분의 작은 움직임 | 표정·눈매의 짧은 변화, 원래 포즈로 복귀 | 손가락/머리 장식 위치와 비대칭 유지 |

- IDLE은 *머리·눈·팔·머리카락 등 실제 파츠 변화*가 보이는 원본 기반 프레임이어야 한다. 전체 PNG나 창만 흔들어 움직임을 가장하지 않는다.
- REACT는 1회 재생 후 원래 상태로 복귀한다. 무한 루프 금지.
- WALK는 발/다리의 교차와 중심 이동을 표현하되, 정면 걷기와 측면 걷기 중 하나를 사용자에게 실제 시각 샘플로 보여준 뒤 선택한다. **정면을 유지한 발걸음을 1차 프로토타입 방향으로 제안**한다. 원본 인물을 좌우 반전하면 비대칭 포즈·장식도 반전되는 문제가 있으므로 자동 미러링을 기본안으로 확정하지 않는다.
- SIT/SLEEP은 현재 서 있는 원본과 자세가 많이 달라지는 신규 리소스가 필요하다. IDLE→WALK→REACT 품질을 먼저 확인하고 별도로 설계/승인한다.
- DRAG는 기존 사용자 입력 동작을 유지하되, 자율 이동 중단 → 창 드래그 → 현재 창 위치 동기화 → 다음 상태 복귀라는 흐름을 보호한다. 새 드래그 포즈도 별도 승인 필요.

## 3. 단계별 시각 프로토타입 — 코드 수정 전

1. **지우 IDLE**: 승인 정적 PNG에서 눈/머리카락 등 필요한 국소 영역만 분리한 최소 시각 프로토타입. 원본과 나란히 보기, 첫 프레임과 마지막 프레임 정합성 확인.
2. 승인 후 **설윤·세은 IDLE**: 동일한 방식으로, 승인 원본 픽셀 보존. 한 번에 세 캐릭터 전체를 AI 재생성하지 않음.
3. **지우 WALK 정면 샘플**: 다리/발 움직임이 구별되고 옷·얼굴·손 포즈가 고정되는지 확인.
4. **REACT 샘플**: 1회 반응→IDLE 복귀. 캐릭터별 표정/손 움직임 사용자 승인.
5. **SIT/SLEEP, 방향 표현**: 동작 방식과 그림을 따로 승인한 뒤 작업.
6. 최종 승인 뒤에만 별도 개발 브랜치에서 Electron 통합 및 회귀검증.

각 단계는 실제 움직이는 샘플로 평가해야 하며, 한 장의 정적 이미지를 '동작 검증 완료'로 보고하지 않는다.

## 4. Electron 통합 전에 필요한 검증 (미실행)

- 승인 PNG는 정적 기준만 마련된 상태. 배경 알파/안티앨리어싱/헤어와 스커트 가장자리 품질을 확인하고 필요한 경우 **복제본**으로 분리한다.
- 180×150 DIP 창/110×110 클릭 판정에서 SD의 머리·팔·치마가 잘리거나 클릭되지 않을 수 있음. 실측한 SD 외형 영역과 창 크기를 기준으로 사용자가 볼 수 있는 변경을 별도 승인한다.
- 새로운 캐릭터들은 기존 5종을 덮어쓰지 말고 캐릭터별 모듈로 확장한다. `main`, IPC, `pet-engine.js`, 기존 시작/설명서/이스터에그는 승인 없는 수정 금지.
- 통합 후 Windows Electron 창 오버레이·항상 위·드래그·우클릭 종료·투명 영역 클릭 통과·화면/다중 모니터 경계·DPI·선택/종료 회귀를 별도로 검사한다. 브라우저만으로 Electron/EXE 동작을 검증했다고 말하지 않는다.
- 신규 리소스의 2차 가공/공개 배포 권한 문제는 배포 전에 별도로 검토한다.

## 5. 확정되지 않은 사용자 가시 UX 선택

- **걷기 시 보기 방향**: A) 정면 유지 + 실제 발걸음 (승인 이미지 식별력 우선), B) 좌우/사선 전용 프레임 (표현력 높지만 신규 그림 제작 및 외형 변화 위험).
- **실행 방식**: 기존처럼 **한 번에 1명 선택** (현재 앱 UX 보호; 권장 기본) vs 동시에 3명 표시 (별도 OS 창/충돌/동작 관리 범위가 크게 증가함).
- **움직이는 프레임 승인**: IDLE을 먼저 제작해 미리보기로 확인하고 그다음 WALK/REACT로 확대.

결정되기 전에는 임의로 새 행동, 기본 시간/확률, 배포/런타임 통합을 확정하지 않는다.
